# 左サイドバーの階層ツリー化（フォルダ対応）設計

日付: 2026-08-08
ステータス: 設計承認済み

## 背景と目的

現在、Hugoサイトの左サイドバー（`hugo-theme-docs` テーマの `_partials/sidebar-left.html`）は、スペース内の全ページをタイトル順にフラットに並べているだけである。Confluenceと同じように親子関係に基づく階層ツリーで表示し、Confluenceのフォルダ（v2 APIのfolderコンテンツタイプ）にも対応する。

現状の課題:

- ページのフロントマターに `parent`（親ページのタイトル）はあるが、サイドバーはそれを利用していない
- Go移行ツールはフォルダを一切取得しておらず、親がフォルダのページは親情報を解決できない
- Confluenceサイドバーでの並び順（position）が失われ、タイトルの文字コード順になっている

## 要件（確定事項）

- **開閉式ツリー**: 子を持つ項目に▶アイコンを付け、クリックで展開/折りたたみできる。現在ページの祖先は自動で展開する
- **フォルダは開閉のみ**: Confluenceと同じく、フォルダはクリックしてもページを開かず、子の開閉だけを行うグループラベル。フォルダアイコンでページと区別する
- **URLとディレクトリはフラットのまま**: `content/<スペース>/<ページ名>/index.md`、URL `/<スペース>/<ページ名>/` を維持する。階層はフロントマターの情報だけで表現する
- **並び順はConfluenceを再現**: v2 APIのpositionを取得し、Hugoの `weight` に変換して同一階層内の並び順を再現する

## アーキテクチャ

採用案: **フォルダを「非表示ページ」として出力し、階層・並び順を全てフロントマターで表現する**（検討した代替案は末尾に記載）。

```
Confluence API v2
  ├─ ページ取得（既存）: parentId / parentType / position を追加で利用
  └─ フォルダ取得（新規）: GET /wiki/api/v2/folders/{id}
        ↓
Go移行ツール
  ├─ ページ: フロントマターに parent_id / weight を追加
  └─ フォルダ: 非表示ページ（_build.render = "never"）として出力
        ↓
Hugoテーマ
  └─ sidebar-left.html → 再帰パーシャルで parent_id を辿りツリー描画
```

フォルダもページも `page_id` / `parent_id` の統一キーで扱い、テンプレート側の再帰処理を1本にする。

## Go側の変更

### APIクライアント（confluenceclient.go）

- ページ取得レスポンスから `parentType` と `position` を追加で読み取る（v2 APIのページオブジェクトに含まれるため、エンドポイントの変更は不要）
- `GetFolder(folderID)` を新設: `GET /wiki/api/v2/folders/{id}` でフォルダのタイトル・parentId・parentType・positionを取得
- **フォルダの列挙方式**: 全ページを走査して `parentType == "folder"` の親IDを収集し、`GetFolder` で取得する。取得したフォルダの親がさらにフォルダの場合は再帰的に取得する。スペース内フォルダの一覧APIには依存しない

### Markdown出力（mdwriter.go）

ページのフロントマターに以下を追加する。既存の `parent`（親タイトル）は互換のため残す。

```toml
parent_id = "46923777"   # 親のID（ページまたはフォルダ）。ルート直下なら出力しない
weight = 3               # Confluenceのposition由来の並び順（1以上）
```

フォルダは `content/<スペース>/<フォルダ名>/index.md` として本文なしのスタブを出力する:

```toml
title = "フォルダ名"
page_id = "12345"        # フォルダIDを統一キーとして格納
parent_id = "..."        # ルート直下なら出力しない
weight = 2
is_folder = true
[_build]
  render = "never"       # URLを持たず、HTMLも生成されない
  list = "always"        # ただしテンプレートのページ一覧には現れる
```

- フォルダのディレクトリ名はページと同じ命名規則を使う。既存のページ・フォルダと衝突する場合のみIDサフィックスを付ける（レンダリングされないためURLに影響しない）
- `weight` はHugoで0が「未設定」扱いになるため、`weight = position + 1` として必ず1以上になるよう変換する。positionが取得できない場合はタイトル順の連番で代替する

## テーマ側の変更（hugo-theme-docs）

### サイドバーの再帰化

`_partials/sidebar-left.html` を書き換え、新設の再帰パーシャル `_partials/sidebar-tree.html` を呼び出す。

- セクション内の全ページ（フォルダスタブ含む）から `parent_id → 子リスト` の対応を作り、`parent_id` を持たないノードをルートとしてツリーを描画する
- 各階層は `weight` 順（`.ByWeight`）でソートする
- 見出し（スペースタイトル）は現状どおりh2で維持する

### 開閉UI

`<details>` / `<summary>` 要素を基本とし、JSなしで開閉を実現する。

- 子を持つノード: `<details><summary>▶ タイトル</summary><ul>子…</ul></details>`
  - ページ: `<summary>` 内の `<a>` でリンク。タイトルクリックで遷移、▶部分クリックで開閉
  - フォルダ: リンクなしのラベル＋フォルダアイコン。クリックで開閉のみ
- 子のないページ: 通常の `<li><a>` で描画
- **自動展開**: 現在ページから `parent_id` を遡って祖先集合を作り、祖先の `<details>` に `open` 属性を付与する。現在ページにはCSSクラスで強調表示を付ける
- 開閉状態はページ遷移でリセットされるが、遷移先の祖先が自動展開されるため実用上はConfluenceと同等の見え方になる（状態記憶が必要になったら後からlocalStorageで拡張できる）

## エッジケース

- **親が解決できない**（取得失敗・権限不足・whiteboard等の未対応コンテンツタイプが親）: そのページはルート直下に表示し、移行ログに警告を出す。ページが表示されなくなるよりフラットに出る方が安全
- **空フォルダ**（ページを1つも含まない）: ページの親を辿る列挙方式では発見できないため、サイドバーに表示されない。実害がないため許容する（制限事項）
- **既存データ**: フロントマター追加のため、既存出力に対しては移行の再実行が必要

## テスト

- **Goユニットテスト**（既存スタイルに合わせ `httptest` でモック）
  - `GetFolder` のレスポンス解析
  - ネストしたフォルダの再帰解決（フォルダの親がフォルダのケース）
  - フロントマター生成（parent_id / weight / is_folder / _build）
  - 親解決失敗時のルートフォールバック
- **Hugoテンプレート**: `content/sample` にフォルダスタブ＋階層ページのフィクスチャを追加し、`hugo build` が通ること、`hugo server` での目視確認（ツリー構造・開閉・自動展開・並び順）を行う

## 検討した代替案

- **案B: ツリー全体をJSONデータファイル（`data/sidebar/<スペース>.json`）に出力**: ツリーが1ファイルで見渡せるが、`content/` と `data/` の二重管理になり不整合のリスクがある。ページ検索もページ数に比例して遅くなるため不採用
- **案C: parent_idはフロントマター、フォルダだけデータファイル**: テンプレートがページとフォルダで別処理になり複雑化し、二重管理の欠点も残るため不採用
- **階層ディレクトリへの変更**: URLが階層に依存して不安定になり、ページ間リンクの書き換えも必要になるため不採用（要件でフラット維持を確定済み）
